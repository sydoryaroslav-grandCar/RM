1. Коротко

Це план бойового сайту grandcar.ua: новий web-ua замість WordPress — усі основні сторінки, дані з Public API, заявки, SEO-теги, потім перемикання на прод.

Робимо

  • Кнопки й блоки UI + усі ключові сторінки
  • Підключення каталогу, контенту й форм до API
  • Українська в корені + російська на /ru/
  • Тестовий стенд → переїзд разом із бекендом

Не зупиняє старт FE

  • До 01.11 — малюємо й збираємо сторінки на фейкових даних
  • Живі оголошення — коли бек віддасть каталог по API
  • День відкриття сайту тут не ставимо (чекає і FE, і бек)
Калькулятор: екран і форма — у першій хвилі FE; суми рахує лише бекенд. Коли з’явиться бойовий endpoint — узгоджуємо окремо (або тимчасовий мок).

3. Що входить у бойовий сайт

Простими словами: що робимо в цій хвилі і що свідомо лишаємо на потім.

Робимо зараз

  • Усі головні сторінки як на проді: головна, каталог, лоти, Корея, VIN, статті, обране, sitemap…
  • Кнопки/фільтри + самі сторінки + підключення до API
  • Форми заявок, пошук у шапці, SEO-теги (title, description…)
  • Посадкові з фільтром — той самий /cars/ з фільтром у адресі (не окремі сайти)
  • Перевірка, підчистка, участь у переїзді з WordPress

Не зараз (пізніше / не верстка)

  • Повна таблиця старих URL → куди редіректити (роблять SEO + бекенд)
  • Розбір Google Search Console — не задача верстки

7. Принципи

Принцип

Єдина бібліотека компонентів

Одна кнопка, одне модальне вікно, спільні фільтри. Перелік і години — каталог · сторінки + API · скріни.

Принцип

Мобільний у пікселях · десктоп у rem

Навіщо: сирі px лише під один монітор ламають інші ширини.

  • Телефон — композиція в px.
  • Планшет до редизайну — як телефон.
  • Комп’ютер — відступи/шрифти/радіуси в rem від однієї шкали.
Рішення про якість верстки, не про SEO. Сайт один, HTML один.
Принцип

Калькулятор у першій хвилі FE

Екран і форма на фронті в першій хвилі. Суми рахує бекенд через API; у браузері формули не дублюємо.

Факт

Переходи між сторінками

Next App Router: оболонка лишається, підвантажується потрібний шмат сторінки. Окремо не обговорюємо — нормальна робота стеку.

Узгоджено

Чат — Telegram

Швидкі UX-питання — у Telegram-чаті міграції. Учасники: уся команда.

8. Що потрібно від бекенду

Без цього фронт або стоїть на фейкових даних, або не може показати бойове. Коди Б0, Б1… — етапи з роадмапу бекенду (не наші задачі).

  • Опис API (які запити й поля) — їхній Б0 / контракт до Б1
  • Приклади відповідей: успіх / порожньо / помилка
  • Каталог по API до 01.11 — їхній Б1 (живі оголошення)
  • У відповідях — готові посилання на картинки
  • Прийом заявок і контент — їхні Б5 / Б6
  • Розрахунок калькулятора — узгодити дату (у беку calc може бути пізніше)

9. Середовище для перевірки

  • Спочатку — локальний запуск + preview гілки
  • Коли є перші екрани — спільний staging URL для команди
  • CI на pull request — разом із регулярними збірками

10. SEO у верстці

Опираємось на SEO-аудит (жовтень 2026). Джерело: Google Doc (копія також у assets-from-production/).

  • Один H1; title / description з даних API
  • Один canonical; hreflang uk ↔ ru
  • Розміри картинок, lazy, пріоритет головного фото
  • Schema з полів API — за шаблоном з бекенду

11. Паралельно: Google Search Console

Sitemap з продакшену (~1.4M URL) уже є. Бракує картини індексації. Фронт цим не верстає; потрібно до cutover (SEO + бекенд).

  • Ефективність → Сторінки — кліки, покази, CTR, позиція

Куди: assets-from-production/gsc/. Далі матриця URL перед перемиканням домену.
