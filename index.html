1. Коротко

Це план бойового сайту grandcar.ua: новий web-ua замість WordPress — усі основні сторінки, дані з Public API, заявки, SEO shell, потім cutover на прод. Казахстан і seller portal не входять.

Робимо

  • Бібліотеку UI + збірку всіх ключових URL
  • Підключення каталогу, контенту, форм до API
  • uk у корені + /ru/
  • Staging FE → cutover разом із бекендом

Не блокує старт

  • До Б1 (01.11) — верстка й сторінки на моках
  • Бойовий каталог — після Public API
  • Дата go-live сайту = max(FE, BE gate 12.04.2027, ролі)
Калькулятор: UI в першій хвилі FE; суми лише з бекенд API. У бекенд-роадмапі calc після MVP — узгодити з PO, коли з’явиться endpoint (або мок до нього).

3. Обсяг MVP

Входить

  • Усі основні шаблони з продакшену (Home, /cars/, лоти, korea, VIN, CMS, blog, favorites, sitemap…)
  • Компоненти UI + сторінки + Public API wiring
  • Форми заявок, пошук у шапці, SEO-теги
  • Посадкові з фільтрами = той самий /cars/ + фільтр у URL
  • QA / polish / участь у cutover

Не входить (пізніше)

  • grandcar.kz, marketplace, seller portal
  • en-UA як активна локаль
  • Кампанії / A/B (ADR-030)
  • Повна SEO-матриця legacy-URL (власник SEO + BE)
  • GSC-аналітика як задача верстки

7. Принципи

Принцип

Єдина бібліотека компонентів

Одна кнопка, одне модальне вікно, спільні фільтри. Перелік і години — каталог · сторінки + API · скріни.

Принцип

Мобільний у пікселях · десктоп у rem

Навіщо: сирі px лише під один монітор ламають інші ширини.

  • Телефон — композиція в px.
  • Планшет до редизайну — як телефон.
  • Комп’ютер — відступи/шрифти/радіуси в rem від однієї шкали.
Рішення про якість верстки, не про SEO. Сайт один, HTML один.
Принцип

Калькулятор у першій хвилі FE

Екран і форма на фронті в MVP. Суми рахує бекенд через API; у браузері формули не дублюємо.

Факт

Переходи між сторінками

Next App Router: оболонка лишається, підвантажується потрібний шмат сторінки. Окремо не обговорюємо — нормальна робота стеку.

Узгоджено

Чат — Telegram

Швидкі UX-питання — у Telegram-чаті міграції. Учасники: уся команда.

8. Що потрібно від бекенду

Умова роботи фронту (синхрон з віхами Б*).

  • Опис ендпоінтів (OpenAPI) і полів JSON для TypeScript — Б0/Б1
  • Приклади відповідей (успіх / порожньо / помилка)
  • Public API каталогу — Б1 до 01.11
  • Готові URL картинок у відповідях
  • Прийом заявок / контент API — Б5/Б6
  • Endpoint розрахунку калькулятора — узгодити строк (у BE calc після MVP)

9. Середовище для перевірки

  • Спочатку — локальний запуск + preview гілки
  • Коли є перші екрани — спільний staging URL для команди
  • CI на pull request — разом із регулярними збірками

10. SEO у верстці

Опираємось на SEO-аудит (жовтень 2026). Джерело: Google Doc (копія також у assets-from-production/).

  • Один H1; title / description з даних API
  • Один canonical; hreflang uk ↔ ru
  • Розміри картинок, lazy, пріоритет головного фото
  • Schema з полів API — за шаблоном з бекенду

11. Паралельно: Google Search Console

Sitemap з продакшену (~1.4M URL) уже є. Бракує картини індексації. Фронт цим не верстає; потрібно до cutover (SEO + бекенд).

Запит до команди

  • Індексація → Сторінки — повний експорт
  • Ефективність → Сторінки — кліки, покази, CTR, позиція
  • Карти сайту — статус підключених sitemap

Куди: assets-from-production/gsc/. Далі матриця URL перед перемиканням домену.
